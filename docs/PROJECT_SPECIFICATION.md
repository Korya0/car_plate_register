# Car Register — Project Specification

**Version:** 1.3

## 1. Project Overview

تطبيق Android باستخدام Flutter لتسجيل وإدارة أرقام بروشورات السيارات، مع إمكانية الوصول لنفس البيانات من عدة أجهزة، ودعم العمل بدون إنترنت والمزامنة التلقائية.

## 2. Functional Requirements

### 2.1. Brochure Numbers

- إضافة أرقام البروشورات وحفظها.
- الرقم يتكون من رقم إلى 4 أرقام فقط.
- السماح بالصفر في بداية الرقم، مثل `007`.
- تخزين الرقم كـ `String` للحفاظ على الصفر في البداية.
- عرض الأرقام في قائمة مع وقت الإضافة.
- البحث عن الأرقام.
- حذف رقم مع تأكيد الحذف.
- عرض عدد الأرقام المسجلة.

### 2.2. Shared Data

- مشاركة نفس البيانات بين عدة أجهزة.
- استخدام Shared Access PIN واحد للعميل.
- العميل يدخل الكود مرة واحدة عند ربط كل جهاز.
- لا يُطلب الكود عند فتح التطبيق أو إضافة الأرقام أو حذفها أو تنفيذ أي عملية عادية، بما فيها حذف كل الأرقام.
- مزامنة الإضافات والحذف بين الأجهزة.
- توفير آلية لإلغاء صلاحية جهاز مفقود أو تغيير كود الربط عند الحاجة.
- لا يوجد تسجيل دخول تقليدي بالبريد الإلكتروني وكلمة المرور.
- لا توجد شاشة داخل التطبيق لإنشاء كود Share أو عرضه.

### 2.3. Offline & Synchronization

- العمل دون إنترنت باستخدام قاعدة بيانات محلية.
- حفظ التغييرات محليًا ومزامنتها عند عودة الإنترنت.
- منع تكرار السجلات بسبب إعادة المحاولة.
- منع ظهور السجلات المحذوفة مرة أخرى بعد المزامنة.
- التعامل مع التعارضات عند استخدام عدة أجهزة.

### 2.4. App Lock

- إمكانية قفل التطبيق باستخدام PIN محلي.
- دعم البصمة عند توفرها وتفعيلها.
- فصل قفل التطبيق عن Shared Access PIN.

### 2.5. CSV

- استيراد وتصدير الأرقام بصيغة CSV.
- الحفاظ على الأصفار في بداية الأرقام.
- التحقق من صحة البيانات المستوردة.

## 3. UI/UX Requirements

- واجهة عربية بالكامل باتجاه RTL.
- استخدام Theme واحد في الإصدار الأول.
- تصميم الواجهة تدريجيًا أثناء التطوير.
- واجهة لإضافة الأرقام وعرضها والبحث فيها وحذفها.
- عرض العداد وحالات التحميل والأخطاء والقائمة الفارغة.
- تأكيد واضح قبل حذف كل الأرقام.

## 4. Technical Architecture

| Component | Technology |
|---|---|
| Framework | Flutter |
| Language | Dart |
| State Management | Riverpod |
| Local Database | SQLite / Drift |
| Cloud Database | Firebase Firestore |
| Architecture | Feature-First Clean Architecture |
| Testing | Unit, Widget, Integration Tests |
| CI/CD | GitHub Actions |
| Delivery | Signed Android APK |

The current Firebase configuration is Android-only. Browser runs skip Firebase
initialization and are for local preview; Firebase-backed web features require
registering a web app and adding its FlutterFire configuration.

### Architecture Rules

- فصل Presentation وDomain وData.
- فصل منطق الأعمال عن الواجهات.
- استخدام معالجة أخطاء منظمة ونتائج واضحة.
- تنظيم الكود حسب Features.

## 5. Database & Security

### Brochure Record

- `id`: معرف فريد للسجل.
- `brochureNumber`: رقم البروشور بصيغة String.
- `createdAt`: وقت الإضافة.
- حقول إضافية للمزامنة والحذف عند الحاجة.

### Security

- التحقق من Shared Access PIN على الخادم.
- ربط كل جهاز مصرح له بمجموعة بيانات العميل.
- حماية البيانات باستخدام Firestore Security Rules.
- منع الوصول إلى بيانات غير مصرح بها.
- منع محاولات التخمين المتكررة لكود الربط.
- عدم تخزين مفاتيح الإدارة السرية داخل التطبيق.
- تخزين معلومات التفويض المحلية بطريقة آمنة.

## 6. Testing & Performance

- اختبار التحقق من الأرقام والحفاظ على الأصفار.
- اختبار الإضافة والبحث والحذف والعداد.
- اختبار العمل دون إنترنت والمزامنة بين الأجهزة.
- اختبار Shared Access PIN وصلاحيات الأجهزة.
- اختبار حذف كل الأرقام والتعارضات أثناء المزامنة.
- اختبار الأداء باستخدام 100,000 سجل.
- تشغيل التحليل الثابت والاختبارات عبر GitHub Actions.

## 7. Delivery Requirements

- تسليم APK موقّع وقابل للتثبيت مباشرة.
- تسليم الكود المصدري.
- إعداد Firebase وقواعد الأمان والوظائف المطلوبة.
- توفير اختبارات ووثائق تشغيل وبناء أساسية.
- لا حاجة إلى نشر التطبيق على Google Play.

## 8. Pending Decisions

- طول وصيغة Shared Access PIN وطريقة إنشائه وتغييره.
- سياسة الأرقام المكررة.
- سياسة حل التعارضات عند الحذف وإعادة الإضافة من أجهزة مختلفة.
- أقل إصدار Android مدعوم.
- آلية استعادة PIN المحلي.
- طريقة الإدارة الخارجية لكود الربط وإلغاء صلاحيات الأجهزة.

## 9. Definition of Done

يُعتبر المشروع جاهزًا عند تنفيذ المتطلبات المعتمدة، واجتياز الاختبارات الأساسية، والتأكد من عمل التخزين المحلي والمزامنة والأمان على الأجهزة المستهدفة، وتسليم APK موقّع وجاهز للتثبيت.
